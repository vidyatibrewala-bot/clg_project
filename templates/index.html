Technical Architecture & Project Defense Reference

1. How does the conflict engine prevent double-booking?

The system uses interval intersection mathematics: Two intervals [S1, E1] and [S2, E2] overlap if and only if max(S1, S2) < min(E1, E2). In SQL, this evaluates as:
WHERE existing.start_time < new_end AND existing.end_time > new_start. Standardized 24-hour lexicographical timestamps ensure zero double-booking collisions.

2. What is the role-based security hierarchy?

The application supports 4 distinct personas:
• Student: Quick bookings for study pods and team rooms.
• Professor: Direct access to academic plenaries and seminar halls.
• Lab Assistant: Hardware kit custody and testbench checkouts.
• Campus Manager: Full administrative authority to approve/reject bookings and review occupancy logs.

3. How is database concurrency handled?

SQLite provides ACID transactions. The conflict check and booking insertion occur within database transactions to prevent race conditions during simultaneous requests.

4. How does the Digital Room Pass work?

Each confirmed booking generates a unique ticket code (e.g., BKG-101) and derives a reproducible 4-digit door keypad PIN from the booking ID, allowing keyless electronic smart lock access.
